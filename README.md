# My家計簿

iPhoneのSafariからホーム画面へ追加して使う、自分専用の家計簿PWAです。現在は **Phase 6（予算超過通知）** まで実装しています。

## 実装済み

### Phase 1：アプリ基盤

- React + TypeScript + Vite
- TypeScript strict mode
- iPhone優先のレスポンシブUI、Safe Area、ライト・ダークモード
- PWA manifest、Service Worker、オフライン用アプリシェル、更新通知
- GitHub Pagesのサブパス対応とGitHub Actionsによる自動検査・デプロイ
- React移行前のLocalStorageデータを確認・書き出しできる旧版互換画面

### Phase 2：IndexedDB保存基盤

- Dexieを使用した端末内IndexedDB
- 収支、カテゴリ、支払い方法、予算、通知状態、設定、アプリ情報の型とテーブル
- 初期マスターデータ、データバージョン、マイグレーション
- Repository層とfake-indexeddbによる保存テスト

### Phase 3：収支管理

- 支出・収入の手入力
- 金額は日本円・1円単位で、0円以下は登録不可
- 月単位の切替、検索、絞り込み、詳細、編集、削除
- カテゴリと支払い方法の管理

### Phase 4：集計とホーム

- 選択月の収入・支出・残額
- 前月との差額
- カテゴリ別支出の円グラフ
- 支払い方法別集計
- 収支一覧の絞り込み結果集計

### Phase 5：月予算

- 月全体の予算設定・変更・削除
- 月予算、使用額、残額または超過額、使用率を表示
- 前月の正の未使用予算を翌月へ繰り越す設定
- 過去月の支出・予算変更後に翌月以降の繰越額を再計算
- ホーム画面に選択月の予算状況を表示

### Phase 6：予算超過通知

- 月予算を実際に超えたときだけ通知
- 予算と同額、または予算へ近づいただけでは通知しない
- アプリ内の予算超過バナー
- バナーから対象月の予算画面へ移動
- 対応環境でのシステム通知
- システム通知の権限は設定画面のボタン操作時だけ要求
- アプリ内通知とシステム通知を個別にON・OFF
- 同じ月・同じ通知方法では1回だけ通知
- 通知日時と初回超過日時をIndexedDBへ保存
- システム通知の表示失敗時は次回再試行
- 支出・予算・繰越設定の変更後に現在月を再判定
- 通知失敗が家計簿本体の利用を妨げない設計

カテゴリ別予算とカテゴリ別通知は全体仕様の対象外です。CSV、PDF、バックアップ、レシート入力は後続フェーズです。

## Phase 6の手動確認

### アプリ内通知

1. 現在月の月予算を10,000円に設定します。
2. 現在月の支出合計を10,000円にし、通知されないことを確認します。
3. 支出を追加または編集して合計を10,001円以上にします。
4. 画面上部に「月予算を超過しました」と表示されることを確認します。
5. 「予算を確認」を押し、現在月の予算画面へ移動することを確認します。
6. アプリを再読み込みし、同じ月のアプリ内通知が再表示されないことを確認します。
7. 設定でアプリ内通知をOFFにし、別の未通知月で超過してもバナーが表示されないことを確認します。

### システム通知

1. iPhoneではSafariでアプリをホーム画面へ追加し、ホーム画面から起動します。
2. 設定の「予算超過の通知」を開きます。
3. 画面を開いただけでは通知権限を求められないことを確認します。
4. 「システム通知を許可」を押したときだけ権限確認が表示されることを確認します。
5. 許可後、システム通知がONになることを確認します。
6. 未通知の現在月で予算を超過し、端末通知が1回表示されることを確認します。
7. 再読み込みや画面移動で同じ通知が繰り返されないことを確認します。
8. システム通知をOFFにし、アプリ内通知だけを利用できることを確認します。
9. 権限を拒否した場合、アプリ本体とアプリ内通知が引き続き動作することを確認します。

### 再判定

1. 現在月の支出を予算以下から予算超過へ編集し、通知されることを確認します。
2. 現在月の予算を引き下げて超過状態にし、通知されることを確認します。
3. 繰越設定または前月データの変更で現在月の有効予算が下がり、超過した場合に通知されることを確認します。
4. 過去月を表示しただけでは、過去月のシステム通知が新規表示されないことを確認します。

### 表示確認

- 320px、375px、390px、430px幅
- ライトモードとダークモード
- Safe Areaと下部タブとの重なり
- 長い金額の折り返し
- VoiceOverで通知見出し、本文、ボタンを読み取れること

## IndexedDBの確認

開発者ツールの **Application > Storage > IndexedDB > my-kakeibo** で次を確認します。

- `notificationSettings`：アプリ内通知、システム通知、権限状態
- `notificationStates`：対象月、初回超過日時、各通知日時
- `monthlyBudgets`：判定対象の月予算
- `transactions`：判定対象の支出

通知判定、通知状態、家計簿データは端末内に保存され、外部サーバーへ送信されません。

## PWAとシステム通知

システム通知はWeb NotificationsとService Workerに対応する環境で利用します。iPhoneでは、対応するiOSバージョンでSafariからホーム画面へ追加したWebアプリとしての利用が必要になる場合があります。ブラウザや端末で通知を拒否した場合、アプリから自動的に権限を戻すことはできません。

## GitHub Pages

`main`ブランチへpushすると`.github/workflows/deploy-pages.yml`がlint、型検査、テスト、ビルドを実行し、成功後にGitHub Pagesへ公開します。Viteの`base`、manifestの`start_url`と`scope`、通知アイコンはリポジトリのサブパスに合わせて設定されます。

## 旧版データへのアクセス

React移行前の記録は、同じオリジンのLocalStorageに`kurashi-kakeibo-v1`として保存されています。新しいアプリの **設定 > 旧版データ > 旧版の家計簿を開く** から確認・JSON書き出しができます。Phase 6では旧版データを自動削除・自動変換しません。

## データ保存とプライバシー

新しい家計簿データ、予算、通知設定、通知済み状態の保存先は、iPhoneまたはブラウザ内のIndexedDBです。集計、予算計算、通知判定は端末内で行い、家計簿データをGitHubリポジトリや外部サーバーへ保存・送信しません。ブラウザのWebサイトデータを削除した場合、端末内データも失われる可能性があります。
