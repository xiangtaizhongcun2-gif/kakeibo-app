# My家計簿

iPhoneのSafariからホーム画面へ追加して使う、自分専用の家計簿PWAです。現在は **Phase 3（収支管理）** まで実装しています。

## 実装済み

### Phase 1：アプリ基盤

- React + TypeScript + Vite
- TypeScript strict mode
- iPhone優先のレスポンシブUI、Safe Area、ライト・ダークモード
- PWA manifest、Service Worker、オフライン用アプリシェル、更新通知
- GitHub Pagesのサブパス対応とGitHub Actionsによる自動検査・デプロイ
- React移行前のLocalStorageデータを確認・書き出しできる旧版互換画面

### Phase 2：IndexedDB保存基盤

- Dexieを使用した端末内IndexedDB
- 収支、カテゴリ、支払い方法、予算、通知状態、設定、アプリ情報の型とテーブル
- 初期マスターデータ、データバージョン、マイグレーション
- Repository層とfake-indexeddbによる保存テスト

### Phase 3：収支管理

- 支出・収入の手入力
- 金額は日本円・1円単位で、0円以下は登録不可
- 日付は今日を初期値として変更可能
- 支出：カテゴリ、支払い方法が必須。店名・内容は任意
- 収入：カテゴリが必須。内容は任意。受取方法・入金先は記録しない
- 月単位の切替と日付ごとのグループ表示
- 新しい日付・登録時刻を上に表示
- 店名・内容の検索
- 種類・日付・カテゴリ・支払い方法による絞り込み
- 詳細表示、編集、削除確認
- 一覧表示項目の選択（初期値：金額・カテゴリ・支払い方法・店名・内容）
- 支出・収入カテゴリの追加、表示・非表示
- 支払い方法の追加と削除
- 使用中の支払い方法を削除した場合、過去データを「未設定」へ変更

集計・ホームダッシュボード、予算計算、通知、CSV、PDF、バックアップ、レシート入力は後続フェーズです。

## Phase 3の手動確認

1. 登録タブで支出を登録します。
2. 金額、日付、カテゴリ、支払い方法が未入力の場合に保存できないことを確認します。
3. 収支一覧へ移動し、登録した月と日付の中に記録が表示されることを確認します。
4. 月の左右ボタンで前月・翌月へ移動します。
5. 店名・内容の検索と、種類・日付・カテゴリ・支払い方法の絞り込みを確認します。
6. 記録を開き、詳細、編集、削除確認を確認します。
7. 設定画面で一覧表示項目を変更し、一覧へ反映されることを確認します。
8. カテゴリを追加・非表示・再表示します。
9. 支払い方法を追加します。使用中の支払い方法を削除すると履歴が「未設定」になることを確認します。
10. ブラウザの開発者ツールで **Application > Storage > IndexedDB > my-kakeibo > transactions** を開き、再読み込み後もデータが残ることを確認します。

## GitHub Pages

`main`ブランチへpushすると`.github/workflows/deploy-pages.yml`がlint、型検査、テスト、ビルドを実行し、成功後にGitHub Pagesへ公開します。Viteの`base`、manifestの`start_url`と`scope`はリポジトリのサブパスに合わせて設定されます。

## 旧版データへのアクセス

React移行前の記録は、同じオリジンのLocalStorageに`kurashi-kakeibo-v1`として保存されています。新しいアプリの **設定 > 旧版データ > 旧版の家計簿を開く** から確認・JSON書き出しができます。Phase 3では旧版データを自動削除・自動変換しません。

## データ保存とプライバシー

新しい家計簿データの保存先は、iPhoneまたはブラウザ内のIndexedDBです。家計簿データをGitHubリポジトリや外部サーバーへ保存・送信しません。ブラウザのWebサイトデータを削除した場合、端末内データも失われる可能性があります。
