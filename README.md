# My家計簿

iPhoneのSafariからホーム画面へ追加して使う、自分専用の家計簿PWAです。現在は **Phase 8（バックアップ・復元）** まで実装しています。

## 実装済み

### Phase 1：アプリ基盤

- React + TypeScript + Vite
- TypeScript strict mode
- iPhone優先のレスポンシブUI、Safe Area、ライト・ダークモード
- PWA manifest、Service Worker、オフライン用アプリシェル、更新通知
- GitHub Pagesのサブパス対応とGitHub Actionsによる自動検査・デプロイ
- React移行前のLocalStorageデータを確認・書き出しできる旧版互換画面

### Phase 2：IndexedDB保存基盤

- Dexieを使用した端末内IndexedDB
- 収支、カテゴリ、支払い方法、予算、通知状態、設定、アプリ情報の型とテーブル
- 初期マスターデータ、データバージョン、マイグレーション
- Repository層とfake-indexeddbによる保存テスト

### Phase 3：収支管理

- 支出・収入の手入力
- 金額は日本円・1円単位で、0円以下は登録不可
- 月単位の切替、検索、絞り込み、詳細、編集、削除
- カテゴリと支払い方法の管理

### Phase 4：集計とホーム

- 選択月の収入・支出・残額
- 前月との差額
- カテゴリ別支出の円グラフ
- 支払い方法別集計
- 収支一覧の絞り込み結果集計

### Phase 5：月予算

- 月全体の予算設定・変更・削除
- 月予算、使用額、残額または超過額、使用率を表示
- 前月の正の未使用予算を翌月へ繰り越す設定
- 過去月の支出・予算変更後に翌月以降の繰越額を再計算
- ホーム画面に選択月の予算状況を表示

### Phase 6：予算超過通知

- 月予算を実際に超えたときだけ通知
- アプリ内通知と対応環境でのシステム通知
- 通知権限は設定画面のボタン操作時だけ要求
- 同じ月・同じ通知方法では1回だけ通知
- 通知設定と通知済み状態をIndexedDBへ保存

### Phase 7：CSV・PDF出力

- 選択月、指定期間、収支一覧の表示中結果をCSVへ出力
- UTF-8 BOM、カンマ、改行、引用符のエスケープ
- 対応環境ではWeb Share API、非対応環境ではダウンロード
- 月次家計簿レポートの印刷用画面
- A4縦向けレイアウトとブラウザのPDF保存・共有
- CSVと印刷用レポートを端末内だけで生成

### Phase 8：バックアップ・復元

- IndexedDB内の全データと設定を1つのJSONへバックアップ
- バックアップ形式バージョン、DB・データバージョン、作成日時を保存
- 対応環境ではWeb Share API、非対応環境ではJSONをダウンロード
- 復元ファイルを選択した段階では現在データを変更しない
- ファイル名、作成日時、収支・カテゴリ・支払い方法・予算の件数を表示
- 最終確認後に現在データと設定をすべて置換
- 形式、必須項目、型、バージョン、金額、日付、重複ID、参照整合性を検証
- カテゴリ・支払い方法の使用回数と収支の参照件数を検証
- 不正ファイルでは復元ボタンを表示せず、現在データを維持
- 全テーブルを1つのDexieトランザクションで置換
- 復元途中の書き込み失敗時は全変更をロールバック
- バックアップ作成・検証・復元は端末内だけで処理

カテゴリ別予算とカテゴリ別通知は全体仕様の対象外です。レシート入力・OCRは後続フェーズです。

## Phase 8のバックアップ対象

次のIndexedDBテーブルをすべてバックアップします。

- `transactions`
- `expenseCategories`
- `incomeCategories`
- `paymentMethods`
- `monthlyBudgets`
- `categoryBudgets`
- `budgetSettings`
- `notificationStates`
- `displaySettings`
- `notificationSettings`
- `onboardingStates`
- `appMetadata`

現在画面では利用していない`categoryBudgets`も、保存基盤に存在する復元情報として含めます。

## 復元ルール

復元は統合ではなく、現在の全データと設定をバックアップ内容へ置き換えます。

1. JSONファイルを選択します。
2. アプリが全項目を検証します。
3. 検証済みの場合だけ、ファイル情報と件数を表示します。
4. 「このバックアップを復元」を押します。
5. 現在データが消えることを明示した最終確認画面を表示します。
6. 「現在のデータを消して復元」を押した場合だけ置換します。

CSV読込、現在データとの統合、クラウドからの自動取得は行いません。

## バックアップの検証

復元前に少なくとも次を検証します。

- My家計簿のバックアップ形式であること
- バックアップ形式バージョン
- データベースバージョンとデータバージョン
- 全テーブルの必須項目
- 文字列、真偽値、整数、配列、オブジェクトなどの型
- 金額が安全な整数であること
- 実在する日付・月・UTC日時
- 収支、カテゴリ、支払い方法、通知状態などの重複ID
- 固定IDの設定データが1件ずつ存在すること
- 支出・収入とカテゴリ、支払い方法の参照整合性
- カテゴリ予算・通知状態と支出カテゴリの参照整合性
- 使用回数と実際の収支参照件数
- 基本予算、繰越額、有効予算の整合性
- システム管理の「未設定」支払い方法

検証が成功する前にIndexedDBを削除・変更しません。

## Phase 8の手動確認

### バックアップ作成

1. 収支、月予算、カテゴリ、支払い方法、表示設定、通知設定を変更します。
2. 設定画面の「バックアップ・復元」を開きます。
3. 「全データをバックアップ」を押します。
4. iPhoneでは共有シート、非対応ブラウザではダウンロードが開始することを確認します。
5. ファイル名が`my-kakeibo-backup-YYYYMMDD-HHmmssZ.json`形式であることを確認します。
6. 共有をキャンセルしても家計簿データが変化しないことを確認します。

### 正常な復元

1. バックアップ作成後、収支や設定を変更します。
2. 「バックアップファイルを選択」から作成したJSONを選びます。
3. 選択直後には現在データが変わらないことを確認します。
4. ファイル名、作成日時、件数が正しいことを確認します。
5. 「このバックアップを復元」を押します。
6. 現在データと設定がすべて消える警告を確認します。
7. 一度キャンセルし、現在データが残ることを確認します。
8. 再度確認画面を開き「現在のデータを消して復元」を押します。
9. 収支、カテゴリ、支払い方法、予算、表示設定、通知設定がバックアップ時点へ戻ることを確認します。
10. アプリを再読み込みしても復元内容が残ることを確認します。

### 不正ファイル

次のファイルを選び、復元できず現在データが残ることを確認します。

- 壊れたJSON
- 他アプリのJSON
- 必須項目を削除したJSON
- 形式バージョンを変更したJSON
- 0円・負数・小数など不正な金額を含むJSON
- 存在しない日付を含むJSON
- IDを重複させたJSON
- 存在しないカテゴリや支払い方法を参照するJSON
- 使用回数を改変したJSON

不正ファイルでは「このバックアップを復元」ボタンが表示されないことも確認します。

## IndexedDBの確認

開発者ツールの **Application > Storage > IndexedDB > my-kakeibo** で、復元前後に全テーブルの内容が置き換わることを確認します。

不正ファイル、確認画面のキャンセル、復元途中の失敗では、既存テーブルが部分的に消えない設計です。

## PWAとオフライン

アプリ本体と必要なJavaScriptがService Workerへキャッシュ済みで、IndexedDBを利用できる状態では、JSONの作成、検証、復元を端末内で行います。ブラウザやOSの共有画面とファイル選択画面は端末環境に依存します。

## GitHub Pages

`main`ブランチへpushすると`.github/workflows/deploy-pages.yml`がlint、型検査、テスト、ビルドを実行し、成功後にGitHub Pagesへ公開します。Viteの`base`、manifestの`start_url`と`scope`はリポジトリのサブパスに合わせて設定されます。Phase 8は外部URLや固定ルートを使用しません。

## 旧版データへのアクセス

React移行前の記録は、同じオリジンのLocalStorageに`kurashi-kakeibo-v1`として保存されています。新しいアプリの **設定 > 旧版データ > 旧版の家計簿を開く** から確認・JSON書き出しができます。旧版JSONはPhase 8の新しいバックアップ形式とは異なるため、そのまま復元できません。

## データ保存とプライバシー

新しい家計簿データ、予算、通知設定、通知済み状態の保存先は、iPhoneまたはブラウザ内のIndexedDBです。集計、予算計算、通知判定、CSV・レポート作成、バックアップ作成・検証・復元は端末内で行います。

Web Share APIを選択した場合、ユーザーが共有シートで選んだ保存先・アプリへJSONファイルを渡します。アプリが家計簿データをGitHubリポジトリや独自の外部サーバーへ自動送信することはありません。ブラウザのWebサイトデータを削除した場合、端末内データも失われる可能性があるため、定期的にバックアップファイルを保存してください。
